# 02 AI 接入：全配置，不改代码

内核里**没有模型名、没有厂商名**。要换模型，只改 `config/providers.yaml` 与 `config/agents.yaml`。

## 两层结构

```
流水线角色（decomposer / implementer / reviewer）
        ↓ agents.yaml 路由选择
agent（prompt + 温度 + max_tokens）
        ↓ agent.provider
provider（协议 + 端点 + 模型 + 密钥来源）
```

## provider 三种形态

```yaml
providers:
  openai-compatible:            # OpenAI 及绝大多数兼容端点
    kind: openai-compatible
    base_url: "https://api.example.com/v1"
    model: "gpt-4.1"
    api_key_env: "PLATFORM_LLM_API_KEY"

  anthropic:
    kind: anthropic
    base_url: "https://api.anthropic.com"
    model: "claude-sonnet-4"
    api_key_env: "ANTHROPIC_API_KEY"
    anthropic_version: "2023-06-01"

  local-agent:                  # 内网/容器内的 agent CLI
    kind: cli
    command: "node tools/local-agent.mjs"
```

**密钥永不写进配置**，只写环境变量名（`api_key_env`）。`doctor` 会提示哪个变量没设置，dry-run 会脱敏展示。

## 角色路由

```yaml
agents:
  implementer:
    provider: openai-compatible
    prompt: prompts/implement.md
    temperature: 0.1

  local-implementer:
    provider: local-agent
    prompt: prompts/implement.md

routing:
  default: decomposer       # 兜底
  by_role:
    implementer: implementer
  by_project: {}            # 项目级覆盖，优先级最高
```

优先级：`by_project[项目][角色]` → `by_role[角色]` → `default`。
项目侧写在 `projects/<id>/project.yaml`：

```yaml
ai:
  routing:
    implementer: local-implementer   # 这个项目的实现者走本地 agent
```

本仓库实测：`ledger-cli` 的 implementer 解析到 `local-agent (cli)`，reviewer 解析到 `anthropic (http)`，
order-cancel 走默认 `openai-compatible` —— 三套路由并存，内核无分支代码。

## 验证与上线

```bash
node platform/cli.mjs agents --project ledger-cli --role reviewer
```

输出的是**将要发送的真实请求**（url / header 名 / body / 密钥来源），不发请求、不花钱。
这能覆盖 90% 的接入错误（模型名错、端点少 `/v1`、header 名不对、prompt 路径错）。

真实调用由 `ai.invoke()` 完成，默认被 `DSH_PLATFORM_ALLOW_NETWORK=1` 挡住 —— 这是刻意的：
模型调用是**唯一会让代码离开内网的动作**，必须显式开启。

## 本地 agent（kind: cli）契约

- 平台把 prompt 写成 JSON 文件，路径通过环境变量 `DSH_PROMPT_FILE` 传入；
- agent 从文件读取，不通过 stdin（跨进程管道在受限环境下不可靠）；
- **stdout 必须是 JSON**，平台解析后交给后续校验（分解产物会被 `plan` 校验，不合格直接拒绝）；
- 退出码非 0 视为失败，进入重试或升级。

这条契约让你不用改平台就能接：Claude Code / 自研 agent / 容器里的 MCP 工具链。

## 三条护栏

1. **输出必须可校验**：分解器产出的是卡 YAML，`plan` 会查 DAG、写域、判据；不合格重试 ≤ 3 次后转人工。
2. **实现者不能改判据**：无论用哪个模型，测试文件都在 `deny_write` 里，diff 越界即失败。
3. **成本可控**：`max_tokens`、`temperature`、超时都在配置里；`evidence` 记录每次调用的 token 与耗时（生产上补 `usage` 字段即可）。

## 换供应商的真实代价

| 变化 | 要改的地方 |
| --- | --- |
| 换模型/换厂商（兼容协议） | `providers.yaml` 一行 |
| 换到不同协议 | `providers.yaml` 的 `kind` |
| 换 prompt | `config/prompts/*.md` |
| 某项目专用模型 | `project.yaml` 的 `ai.routing` |
| 换 agent 实现方式 | `kind: cli` + `command` |

内核代码 **0 行改动**。这是"配置化接入 AI"的可验证含义。
