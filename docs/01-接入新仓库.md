# 01 接入新仓库：5 步清单

目标：接一个新仓/新项目，**只写配置，不改内核代码**。下面每条都对应平台里已经生效的机制。

## Step 1 · 注册项目（1 个文件）

`projects/<id>/project.yaml`：

```yaml
id: payment-service
name: 支付服务
stack: go-stdlib            # 引用 config/presets/<stack>.yaml
repo:
  path: ../../repos/payment-service   # 相对 project.yaml 所在目录
  branch: main
cards:
  mode: platform            # platform：卡在平台侧；repo：卡留在仓库内（零迁移接入）
  spec_dir: spec
  tasks_dir: tasks
policy:
  max_files_per_task: 6
  max_diff_lines: 300
ai:
  routing:
    implementer: local-implementer      # 覆盖默认路由
templates:
  requirement: feature
  task: feature
```

自检：`node platform/cli.mjs doctor --project payment-service`

## Step 2 · 技术栈预设（可选）

栈已存在就跳过。不存在时加 `config/presets/<stack>.yaml`：

```yaml
gates:
  env:
    GOCACHE: "{{platform.root}}/.cache/go-build"   # 缓存必须在沙箱可写目录，且不污染仓库
  build: { command: "go build ./..." }
  lint:  { command: "go vet ./..." }
  test:  { command: "go test ./..." }
```

要求：
- 三条命令都要能用**退出码**表达成败（不要 `|| true`、不要管道接 grep）。
- 单次执行尽量 < 10 分钟；超时由配置控制。
- 命令的工作目录默认是仓库根；需要子目录用 `cwd`。

## Step 3 · 判据先行（最容易被跳过、也最决定成败）

- 把验收测试写进仓库，并确认它们现在是**红的**。
- 每条验收标准在需求卡里用 `verify_by` 指向具体测试文件，`plan` 会检查文件存在。
- 测试文件必须落在 `policy.deny_write` 里（平台默认已包含 `**/*_test.go`、`**/*.test.mjs`）。

写不出验证方式的需求 → 标 `autonomy: human-only`，不要进自动化队列。

## Step 4 · 需求卡与任务卡

```bash
node platform/cli.mjs new-task --project payment-service --template feature \
  --id T-201 --title "支付回调幂等" --requirement REQ-201 \
  --acceptance AC-1,AC-2 --write internal/payment/callback.go --depends T-200 \
  --objective "第一行\n第二行"
```

规则（`plan` 会强制）：
- `scope.write` 落到具体文件/目录，不得是仓库根；
- 两卡写域不相交，相交必须 `depends_on`；
- 每卡 `verify` ≤ 3 条且定向到本模块；
- 最后一卡用全量测试做需求级集成门禁。

## Step 5 · 执行

```bash
node platform/cli.mjs plan    --project payment-service
node platform/cli.mjs prepare --project payment-service --task T-201
#   实现者（人或 agent）在 worktrees/payment-service/T-201 里改代码
node platform/cli.mjs run     --project payment-service --task T-201
```

`run` 的判定顺序：变更非空 → 写域/预算 → 门禁三段 → 提交 → 合并 → 主仓复验 → 归档。
任一步失败都会留下证据包，且**不会**部分合并（主仓复验失败会 `reset --hard` 回滚）。

## 常见坑（都踩过）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| `.gitignore` 误伤目标目录 | 实现写好了但"没有任何变更" | 平台已加拦截：列出被忽略的写域路径。立即修正 `.gitignore` |
| 门禁在错误目录执行 | 测试跑的是主仓而不是 worktree | 内核已修：`resolveVerify(cfg, refs, wt)` |
| 基线陈旧 | 任务验证时依赖还没合并 | 规范：依赖合并后再 `prepare`；`prepare` 对干净 worktree 会强制对齐最新基线 |
| 缓存写进仓库 | diff 里出现成千上万个缓存文件 | 预设里把 `GOCACHE`/`node_modules` 指到平台 `.cache/` |
| 一张卡全量测试 | 任务之间互相阻塞 | 单卡定向测试，只有集成卡用全量 |
| 用 superuser 跑 agent | 越权写系统目录 | 工作区固定在 `worktrees/<project>/<task>`，写域外一律拒绝 |

## 多项目隔离

- 每个项目独立 `worktrees/<project>/`、`runs/<project>/`、`archive/<project>/`。
- 项目之间不共享分支、不共享证据索引（同一份 `index.jsonl`，按 `project` 字段区分）。
- 被管仓库是外部 checkout（`repos/` 在平台 `.gitignore` 里），平台不内嵌代码。
