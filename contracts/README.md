# 契约包 v1（唯一事实来源）

服务端与客户端**都从这里的文件派生**，不允许任何一侧自行设计接口。

| 文件 | 内容 | 谁消费 |
| --- | --- | --- |
| `api.v1.yaml` | HTTP API（OpenAPI 3.1）：路径、信封、错误码、ETag | 服务端实现、客户端 `api.mjs` |
| `db.v1.sql` | 存储模型（SQLite DDL）：实体、约束、索引 | 服务端迁移 |
| `config.schema.v1.json` | 项目/平台配置 JSON Schema | 服务端校验（客户端只读） |
| `agent.schema.v1.json` | agent 配置 + 执行策略 schema | 服务端下发、客户端只读 |
| `ipc.v1.md` | 壳 ↔ 视图 的本地能力契约（文件/终端/agent） | 客户端壳与视图 |

## 版本与兼容

- 路径带大版本：`/api/v1/...`；破坏性变更必须开 `v2`，同时保留 `v1` 至少一个发布周期。
- 响应信封固定：`{ data, meta: { apiVersion, requestId } }`；错误固定 `{ error: { code, message, details? }, meta }`。
- 枚举只允许**追加**，不允许改语义；删除值必须走新版本。
- `schemaVersion` 字段（`project/v1`、`agent/v1`）用于服务端渐进迁移；客户端遇到未知字段必须忽略而不是报错。

## 双写边界（重要）

| 数据 | 写方 | 读方 |
| --- | --- | --- |
| 项目/门禁/预设配置 | **仅服务端** | 客户端只读 |
| agent 配置与执行策略 | **仅服务端** | 客户端只读，按下发内容执行 |
| 需求卡 / 任务卡 | 客户端（含人工编辑）+ 服务端 | 双向，`ETag`+`If-Match` 乐观锁 |
| 运行结果 / 证据 | **仅服务端** | 客户端只读 |

客户端不缓存"权威业务状态"：面板上的一切状态（任务状态、DAG 层级、证据链）都来自服务端计算，
客户端只做渲染与交互。这条是避免长期出现"两边各算一套状态"的根因。

## 乐观锁

所有可写资源返回 `ETag: "v<integer>"`；更新必须带 `If-Match`，不匹配返回 `409 conflict`。
`version` 由服务端单调递增，客户端不得自行构造。
